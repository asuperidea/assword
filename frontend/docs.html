Backend

Setup

If you would like to set up your own backend:

Clone the backend.

Run the following commands:

    python3 -m venv venv
    source venv/bin/activate
    pip install -r requirements.txt
    uvicorn main:app --reload

Create a .env file and add the following:

    JWT_KEY="" # Any string you would like

Directory

Each Python file handles a differnt function.

The .env file holds your JWT secret, never change it unless you restart your entire backend.

Both .db files are the databases that holder users and passwords. The python scripts automatically creates them.

Here's a full breakdown: 

    /backend
        database.py   <- Database Setup
        fakesalts.py  <- Fakes Salts
        jwtfuncs.py   <- JWT Functions
        main.py       <- API setup
        models.py     <- Models

        entries.db    <- Entries
        users.db      <- Users
        .env

Endpoints

The API has seven endpoints to call.

POST .../signup

Signup accepts an email, salt, and authkey via a request body. /signup returns the userId and email in the response body.

GET .../login/start

Login Start accepts a userEmail via a query parameters. /login/start returns the users salt in the response body.

It is important to note that the default backend will fake a salt to avoid leaking what emails are in use. Each fake salt is consistantly made based on the query userEmail. See fakesalts.py

GET .../login/validate

Login Validate accepts a userEmail and authKey via query parameters. /login/validate returns a signed JWT used for all other endpoints.

Login Validate may return a

  • 400 If the email or authKey is expired
  • 200 if the request was successful.

GET .../entry/get

entry/get requires a valid JWT in the HTTPBearer

entry/get returns an array of objects. Each object contains an entryId, ciphertext, and iv.

The default frontend uses the iv to decrypted the ciphertext into a object containing a title, website, username, and password.

entry/get will return a

  • 400 If the JWT is invalid or expired
  • 401 If the JWT is missing
  • 200 if the request was successful.

POST .../entry/new

/entry/new requires a valid JWT in the HTTPBearer

/entry/new accepts ciphertext and iv in the request body. Entry new returns a response body with ciphertext, iv, the userId, and the entryId.

entry/new will create a new password in the backend database. This password is tied to the user.

/entry/new will return a

  • 400 if the JWT is invalid or expired
  • 401 if the JWT is missing
  • 422 if ciphertex or iv is missing.
  • 200 if the request was successful.

POST .../entry/change/

entry/change requires a valid JWT in the HTTPBearer

Via the request body, entry/change accepts the entryId of the entry to be changed with updated cipherText and iv.

entry/change will return a

  • 400 if the JWT is invalid or expired. Or if the userId dosn't match
  • 401 if the JWT is missing.
  • 403 if a entry tied to another user is attempted to be changed
  • 404 if the entryId dosn't exist.
  • 200 if the request was successful.

DELETE ../entry/delete

entry/delete requires a valid JWT in the HTTPBearer

entry/delete will delete an entry based on the entryId. entry/delete checks the given iv aganist the stored iv to make sure the entries match.

Via the request body, entry/delete accepts the entryId and an iv.

entry/delete will return a

  • 400 if the JWT is invalid or expired.
  • 401 if the JWT is missing.
  • 403 if the entry is tied to another users account, not yours.
  • 200 if the request was successful.
