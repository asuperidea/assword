Backend

Setup

If you would like to set up your own backend:

Clone the backend.

Run the following commands:

    python3 -m venv venv
    source venv/bin/activate
    pip install -r requirements.txt
    uvicorn main:app --reload

Create a .env file and add the following:

    JWT_KEY="" # Any string you would like

Directory

Each Python file handles a differnt function.

The .env file holds your JWT secret, never change it unless you restart your entire backend.

Both .db files are the databases that holder users and passwords. The python scripts automatically creates them.

Here's a full breakdown: 

    /backend
        database.py   <- Database Setup
        fakesalts.py  <- Fakes Salts
        jwtfuncs.py   <- JWT Functions
        main.py       <- API setup
        models.py     <- Models

        entries.db    <- Entries
        users.db      <- Users
        .env

Endpoints

The API has seven endpoints to call.

.../signup

Signup accepts an email, salt, and authkey via a request body. /signup returns the userId and email in the response body.

.../login/start

Login Start accepts a userEmail via a query parameters. /login/start returns the users salt in the response body.

It is important to note that the default backend will fake a salt to avoid leaking what emails are in use. Each fake salt is consistantly made based on the query userEmail. See fakesalts.py

.../login/validate

Login Validate accepts a userEmail and authKey via query parameters. /login/validate returns a signed JWT used for all other endpoints.

Login Validate may return a 400 Error if the email or authKey are invaild.

.../entry/get

/entry/get requires a valid JWT in the HTTPBearer

/entry/get returns an array of objects. Each object contains an entryId, ciphertext, and iv.

The default frontend uses the iv to decrypted the ciphertext into a object containing a title, website, username, and password.

/entry/get will return a

  • 400 If the JWT is invalid or expired
  • 401 If the JWT is missing
